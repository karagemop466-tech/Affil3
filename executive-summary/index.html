What is built

  • A publication-style site: front page, five product pages, three category pages, five guides, a comparison table and a source register.
  • A disclosure strip above the fold on every page, repeated in the footer, using the exact wording required by the Associates Operating Agreement S01.
  • A privacy-preserving click counter and a self-hostable collector. The collector is not deployed, so nothing is being measured yet FLG-009.
  • A publishing gate (tools/verify.mjs) that fails the build if a page loses its disclosure, an Amazon link loses rel="sponsored", a row loses its source, or an internal link breaks.
  • A campaign ledger with a defined schema and zero rows. No conversion score and no revenue forecast appear anywhere on this site.

What is verified

  • The disclosure requirement, the tagged-link rule and the price-display restriction, each read from the official Associates pages on 2026-11-20 S01 S02 S03.
  • rel="sponsored" on outbound affiliate links, per Google's guidance S06.
  • The endorsement-disclosure rule, read from 16 CFR 255.5 on eCFR S07.
  • Manufacturer specifications for four of five products, each on the maker's own page S11 S12 S13 S14.
  • USDA safe minimum internal temperatures, quoted from FSIS S10.

What is not verified, and why

  • Which product each submitted short link was meant to reach. The links resolve, but the observed destination is not the same as the owner's intent, and the mapping changed between fetch rounds FLG-001 FLG-002.
  • Whether the buy links credit a sale. No link has been clicked inside an enrolled Associates session FLG-005.
  • The ThermoMaven specifications. No manufacturer page exists for that model FLG-025.
  • Whether the Associates account is active and declares this site FLG-008.

Four decisions only the owner can make

  1. Confirm which product each supplied short link was meant to reach. This closes the largest gap on the site.
  2. Test one Special Link per product in Associates Central, then confirm the click appears in a report.
  3. Deploy the analytics collector, or decide to run with no measurement for now.
  4. Pick a publishing cadence, or the feed will not grow.

Each of those is written up with its trade-offs on the suggestions page.

What this build cannot do

It cannot read Amazon prices, sales, or Associates reports, because that needs authorized API access the build does not have. It does not scrape Amazon. Any figure that would require that data is absent on purpose, not forgotten.

What is live

  • A publication-style front page, a shop with five product cards and a full source register, five individual product pages, a side-by-side comparison, three category clusters and 8 guides.
  • A disclosure strip under the masthead on every page and a repeat in the footer, using the statement required by Operating Agreement §5. Every Amazon link is marked rel="sponsored" and carries the tracking ID.
  • An RSS feed, a sitemap, a 404 page, canonical URLs and structured data. The repository's archive publications are excluded from the index so search engines see one site.
  • A publishing gate (tools/verify.mjs) that fails the build on a missing disclosure, an untagged Amazon link, a price, a broken internal link, a missing image or a source ID that does not exist.

What is verified, and how

  • Operating Agreement §1 and §5 read in full on 2026-11-20: Special Links must use the tagged formats Amazon provides, and the Associates statement must appear clearly and prominently. The Program Policies were read the same day: the tag must be a URL parameter on every link (§2(b)), cloaking is prohibited (§6(v)), a shortener may not obscure the destination (§6(w)), and reviews, ratings and prices may only come from Amazon-served content or the API (§6(t), §2(b)).
  • Google's outbound-link guidance, the FTC endorsement guidance and the USDA temperature chart were read and are linked from every page that uses them.
  • All five submitted short links were followed again today. Each resolved to the same Amazon product page recorded in the register, with the same product ID and title. The intended ASIN still cannot be confirmed from an official source, so it stays blank.

What is blocked, and on what

  • Link validation. One Special Link per product must be generated and tested inside Associates Central. That needs the account, not this build. FLG-005 FLG-009
  • Product intent. Only you can say which product each short link was meant to reach. Until then the intended fields stay blank. FLG-002
  • Measurement. The five events are defined and the collector exists, but no endpoint is deployed, so the live site records nothing. FLG-009
  • Search visibility. Search Console is not connected, so the next topic cannot yet be chosen from measured queries. FLG-013
  • Names and images. There is no named author, no product photography and no prices. Each would need a person, a licence or an API. FLG-014 FLG-015 FLG-016

What changed in this pass

  • The front page was rebuilt as a publication front page: illustrated hero, five product cards, guides, categories, then the records.
  • Five product pages and a comparison page were added. Each product page shows the observed listing, the blank intended fields, the source for every row and what was not verified.
  • Three guides were added to close the oven and thermometer clusters, and every guide now carries a short version, a table of contents, a limits box and buyer questions.
  • The suggestion list became a decision board with three paths, and the question list now separates blocked, open and discoverable gaps.
  • Source links were corrected and re-read: USDA temperature values now cite the chart page directly, and the policy clauses are cited from the current published text rather than an excerpt.

Decisions only you can make

  1. Which product each short link was meant to reach (Q-01).
  2. Whether the account is active and declares this site, and whether the tracking ID belongs to it (Q-03).
  3. Whether to hide buy buttons until link validation passes (S-01).
  4. Which path to take — ship and measure, measure first, or Associates-ready (decision board).

Limits of this build

It cannot pull Amazon product data, prices, sales or commission reports. Those require authorized access — the Creators/PA API or Associates reports — and the sandbox has neither. The site does not scrape Amazon, does not display star ratings, and does not forecast revenue.
