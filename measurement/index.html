Measurement

What this site records, what it deliberately does not, and how the numbers reach the ledger.

The rule

The site's own counter records clicks and reading behaviour. It never records anything that identifies a person. Orders come from Amazon's own report and nowhere else. The two are never mixed in a single number.

The five events

The complete event list. Nothing outside this table is sent.
Event Name Fires when Fields
page_view Page view Once per page load, on every page including 404. path, referrer_host, viewport
outbound_click Outbound affiliate click When a reader clicks a sponsored product link, before navigation. path, product_id, asin, placement
guide_progress Guide read depth At 25%, 50%, 75% and 100% scroll depth on a guide or comparison page. path, depth
table_use Comparison table interaction When a reader sorts, filters or expands a row in a comparison or register table. path, table_id, action, filter
reader_signup Reader capture When a reader submits the newsletter form. path, placement

What is never collected

No IP address

The browser does not send one and the collector does not store one.

No cookies

Nothing is written to a cookie jar. The session id lives in sessionStorage and dies with the tab.

No advertising id

No fingerprinting, no canvas reads, no font or plugin enumeration.

No email addresses

Email is only ever sent to the list provider, never to the collector.

No user agent

Not captured, not forwarded, not stored.

No referrer URL

Only the bare hostname of the referring site, and only when it is a different host. The collector rejects anything that is not a hostname.

Do Not Track honoured

If the browser sends DNT or GPC, no event leaves the page at all.

One honest caveat

This site's collector is IP-free. The hosting platform is not. GitHub's documentation states that when a GitHub Pages site is visited, the visitor's IP address is logged and stored for security purposes, regardless of consent. FLG-012 →

How the collector works

  1. The browser generates a random 128-bit id in sessionStorage. It is never linked to a person, a device or an email address.
  2. Each event is posted to the collector endpoint with the event name, the page path and that event's listed fields.
  3. The collector hashes the id against a server-side salt that never reaches the browser, so the stored record cannot be reversed back into the value that was sent.
  4. The record is appended as one NDJSON line. The collector rejects any event name that is not on the list above.

The collector source is in tools/analytics_sink.py. It is standard library only and runs anywhere Python does.

Where the numbers go

The site's own events and Amazon's report land in the same ledger but never in the same row. The ledger ships empty, with its columns already defined.

Reader capture

The signup form is built and it fires the reader_signup event, but no list provider has been chosen. Until one is, the form tells the reader exactly that and stores nothing. A capture box that quietly discards addresses is worse than no capture box at all.
