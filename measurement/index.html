Measurement

A proposed set of five events. The client records them only when analyticsEndpoint is set in data/config.json; today it is empty, so nothing is sent and no traffic figure exists.

Live status: Inactive. No endpoint is configured, so the browser sends nothing. See suggestion S-03 and flag FLG-009.

The five events

EventFires whenProperties
page_viewOnce per page load.path referrer_host
category_viewOnce per category page load.category
product_viewWhen a product page or product card is rendered in the DOM, once per page load. This records that the element was rendered, not that a reader saw it in the viewport.product_id
outbound_clickWhen a reader clicks a buy link. The link is not redirected; the browser goes straight to the Amazon URL.product_id destination_host placement
guide_read_75When a reader scrolls past 75 percent of a guide. This is a scroll-depth proxy for how far a reader went, not proof that the guide was read.guide

Privacy

No cookies. No IP address stored. No user-agent stored. No fingerprinting. No cross-site identifiers. Counts are aggregated per day, and browsers sending Do Not Track are not counted at all.

Not collected: cookies, IP address, user-agent, account data, anything typed into the page, cross-site identifiers.

Read the privacy notice for the plain-English version.

Why clicks are not routed through a redirect

The Program Policies prohibit cloaking the URL of a site that carries Special Links, including by sending readers indirectly through an intermediate page. A redirect-based click counter is exactly that pattern, so the counter records the click in the browser and lets the link go straight to Amazon. S02
