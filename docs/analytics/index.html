Measurement

Analytics & the campaign ledger

Click and conversion measurement is live in the machinery before anything is optimized. Clicks are counted client-side; conversions are recorded only from authorized first-party reports. No conversion score and no revenue forecast is presented here.

Counter

The outbound click counter

The client (docs/assets/analytics.js) attaches to every outbound Amazon link. On click it records an outbound_click event with the destination host, and sends it to the analytics endpoint. It uses navigator.sendBeacon so the event survives the page unload. There are no cookies, no local storage, and no personal identifiers.

<a href="https://www.amazon.com/dp/B0CDY277D3"
     target="_blank"
     rel="sponsored noopener noreferrer"
     data-outbound="true"
     data-outbound-host="amazon.com">View listing</a>

On hosts without an endpoint (e.g. a bare GitHub Pages build), the client silently no-ops — nothing is stored and nothing breaks. Point it at your endpoint with window.ANALYTICS_ENDPOINT = "https://analytics.example.com/api/collect".

Endpoint

Self-hosted analytics endpoint

The endpoint lives in server/analytics_server.py — standard library only, no dependencies. It accepts POST /api/collect, stores each event as one JSON line, and deliberately stores no IP addresses. Requirements: a host you control (a VPS, a container, or a serverless function with the same contract).

# Deploy (example)
python3 server/analytics_server.py --port 8080   # binds 0.0.0.0

# What it stores, per event:
{"ts": "...", "event": "outbound_click", "path": "/products/", "channel": "organic", "target": "amazon.com"}

# Query the raw log:
tail -f events.jsonl

The endpoint is a first-party collection point. A privacy notice describing purpose, retention, and deletion should be published before real traffic flows (see the Questions register, Q-07, and SG-12).
