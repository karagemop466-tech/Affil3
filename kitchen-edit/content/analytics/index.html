Analytics & campaign ledger

Click and conversion measurement, defined before it exists: five events with a privacy contract, one endpoint decision, and a campaign ledger that starts empty and stays honest. No conversion score or revenue forecast appears anywhere on this site.

The five defined events

Machine-readable: data/events-schema.json. Collector: assets/js/analytics.js.

Privacy contract

  • No cookies. No fingerprinting. No cross-site identifiers. No PII fields in any event schema — payloads are page paths, event names, product IDs and host names.
  • Events queue in the visitor's own browser (localStorage, capped) and are never transmitted until an endpoint is configured; the queue is viewable and exportable by the visitor from the dashboard.
  • GitHub Pages' own access logging (IP for security) is GitHub's, not ours [S10] — we run no server-side logs of our own today.

The endpoint decision (SG-08) — open

OptionShapeCostTrade-off
A — Serverless worker + KVSmall worker function writes events to a KV store (self-hosted code, managed storage)~free at this scaleSelf-hosted control with minimal ops; storage lives with the provider
B — Self-hosted analytics app on a VPSFull self-hosted analytics (e.g., Umami-class) on a small VPS~$5/mo + ops timeComplete control, real dashboards; the most infrastructure
C — Local queue + manual exportsNo endpoint; maintainers export queues from the dashboardfreeZero infrastructure, but no live measurement and tiny sample

Static hosting cannot run the server side [S10] — hence the decision. Choose on the suggestion board; then set window.SHOPNOW_CONFIG.analyticsEndpoint in assets/js/site-config.js.

Campaign ledger — empty by design

The ledger (data/ledger/campaign-ledger.csv) ships with its schema and zero rows. Rows are added only when obtained from authorized first-party reports (Associates Central reports, or the endpoint once live), with a dated provenance trail:

ColumnMeaning
timestampWhen the row was added (ISO date)
sourceWhere the numbers came from (e.g., "Associates Central → Reports → Summary")
channelWhich channel the row covers (site, feed, social)
eligible_sessionsSessions eligible for attribution, as reported
clicksClicks as reported (never inferred from client events alone)
reported_ordersReported orders (first-party only)
provenance_noteDated trail: what was checked, by whom, citing the export
added_bySession or person adding the row
source_urlLink to the report or export the row was taken from
Measure before automating optimization. The brief's Priority 4 directive: no conversion score, no revenue forecast, no "AI optimizer" — until this ledger has real, sourced rows. The CI gate (G-A5) rejects malformed ledger rows, so the ledger can't quietly fill with guesswork.
