Compliance gate

The publishing workflow has two layers: automated checks that run in CI on every push, and manual gates that require account access or judgment and sit in front of anything the checks can't prove. Nothing ships that skips a gate.

Automated — CI on every push (tools/validate.py)

Why G5 is a gate and not a checkbox: the exact compliance status of the submitted short links is unresolved (FLG-003). Only the account holder can resolve it — the site's job is to make that resolution easy (dashboard link pre-check tool, single config file to swap links, kill switch for worst-case) and to make sure nothing on the public site claims more than that.

The publishing workflow, end to end

  1. Pick the next topic from measured queries (Search Console) + reader input — never instinct alone.
  2. Draft in content/, run the fragment generator, add the page to sitemap + feed.
  3. Open a suggestion on the review board if the change alters design, links, or policy — pick the path before implementing.
  4. Push; CI runs the automated gates. Failures stop the merge — fix and retry, never ship broken.
  5. Walk G7/G8 for the new page; log the walk date in the PR description.
  6. Merge; confirm Pages deploy; check the live page's disclosure and sponsored rels once, visually.

The Operating Agreement's participation requirements also shape design decisions: affiliate links stay out of email bodies absent a separate written agreement [S02 clause 6], and no Amazon trademarks/logos are used beyond permitted scopes — hence AI-generated imagery and a wordmark-free Amazon reference throughout.
