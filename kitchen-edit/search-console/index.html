Search Console readiness

Everything the site-side of Google Search Console verification needs is already in place. The only remaining step requires a Google account you control — verification cannot be completed by the site itself. Method reference: Google's ownership-verification guide [S11].

Site-side: done

  • One canonical host: every page declares https://karagemop466-tech.github.io/Affil3/<path> as its canonical URL — one site for search engines to index, no duplicate-host ambiguity.
  • Sitemap: sitemap.xml lists every page with last-modified dates; robots.txt declares it.
  • Feed: feed.xml carries every guide for readers and aggregators.
  • Structured data: JSON-LD Article/Breadcrumb/Organization blocks on every relevant page, generated with the layout.
  • HTML-tag placeholder: the head template carries a marked comment line (Google Search Console HTML-tag verification) — paste the generated meta tag there.

Your-side: the 10-minute checklist

  1. Open search.google.com/search-console and add a URL-prefix property: https://karagemop466-tech.github.io/Affil3/.
  2. Choose the HTML tag method [S11]. Google gives you a <meta name="google-site-verification" content="…"> tag.
  3. Paste that tag into the site head at the marked placeholder (edit tools/build_pages.py, run python3 tools/build_pages.py, commit, push; CI regenerates all pages with it).
  4. Wait for the Pages deploy, then click Verify in Search Console.
  5. Submit https://karagemop466-tech.github.io/Affil3/sitemap.xml under Sitemaps.
  6. Optionally add the HTML-file method as a backup [S11 recommends multiple methods].
Why this matters for the editorial plan: once verified, Search Console's query data is what picks the next guide's topic (Q-09/Q-10) — measured impressions and queries instead of instinct. That's ~30 days away from being useful, so verify early.
