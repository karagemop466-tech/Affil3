Flagged for review

Everything that did not check out

This page is the reason to trust the rest of it. Each item below is a real problem found during verification, with what it affects and how to close it. None of them block the site being useful; all of them block the site being finished.

11 items6 high severityUpdated 2026-11-20
For the reviewer

Nothing on this page prevents the site from going live, and nothing here was quietly dropped. Where a value could not be confirmed from an official source it was left blank in the data and recorded here — no estimate was substituted.

The list, worst first

FLG-001 high severity

The fifth submitted link does not resolve to one stable product

https://link.amazon/B0c8moW59 was requested four times on 2026-11-20 and the destination did not agree between requests. Observation A returned Amazon's interstitial page at /checkpoint/continue with no product. Observation B redirected to amazon.com/dp/B08DKYBTPH, the Chefman TurboFry 8 Qt air fryer. Observation C redirected to amazon.com/dp/B0DHZTCNR5, a ThermoMaven digital meat thermometer. A short link whose destination changes between requests cannot be assigned to a product, because any page written for it would describe whichever product happened to appear.

What it affects: One of five submitted products has no reliable identity. Worse, one of the observed destinations is a product never submitted, which means the link may open the wrong item for a buyer.

How it is handled on the site: Kept out of the product grid and out of the catalogue. The product register shows all three observations with their dates rather than picking one. Every other link on the site is a canonical tagged amazon.com/dp/ URL, which is immune to this class of failure.

How to close itSend the full amazon.com/dp/ URL for the intended product. Do not publish the short link anywhere, and consider removing it from any channel where it is already in use.

Sources: www.amazon.com/checkpoint/continue · www.amazon.com/dp/B0DHZTCNR5

FLG-002 high severity

Submitted short links carry no visible Associates tag in the redirect

The four links that resolved produced redirect targets on amazon.com with tracking parameters such as btn_ref and channelId, but none of the four observed targets contained a tag parameter. Amazon's policies state that the Associates ID or tag must appear as a parameter in the URL of each link placed on the site.

What it affects: It cannot be shown from outside the account that a click through these links attributes to tag shopnow047c-20. This is the single largest commercial risk in the project.

How it is handled on the site: Every outbound product link on this site is a canonical amazon.com/dp/ URL with the tag appended, and the observed redirect is recorded separately in the register rather than being trusted.

How to close itGenerate one link in SiteStripe, compare, then click one supplied link and confirm the click appears in the Associates report before scaling.

Sources: affiliate-program.amazon.com/help/operating/policies

FLG-003 high severity

Associates enrollment and tag ownership are unconfirmed

The tracking ID shopnow047c-20 matches the documented XXXXX-## format and is used throughout the site, but nothing in this environment can confirm that the account is approved, that the tag is active, or that this site is registered against it. Amazon permits Special Links only after applying, and prohibits using a tag assigned to anyone else.

What it affects: If the tag is not active for this site, no commission accrues and the disclosure statement would describe a relationship that does not exist.

How it is handled on the site: Stated plainly on the disclosure page as an item awaiting confirmation rather than asserted as fact.

How to close itSign in to the Associates dashboard, confirm approval status, confirm the tag, and confirm the registered site URL.

Sources: affiliate-program.amazon.com/help/operating/agreement · affiliate-program.amazon.com/help/operating/policies

FLG-006 high severity

The analytics endpoint is not live, so no data is being collected

The site emits five defined, non-identifying events to a documented interface. No collector is configured because no host or privacy decision was supplied. Nothing is currently recorded.

What it affects: No click, view, or product-engagement data exists yet. Any future optimisation claims will need to cite the date collection began.

How it is handled on the site: The measurement page describes the events and states clearly that collection is not yet active.

How to close itSupply an endpoint URL and a retention policy, then set ANALYTICS_ENDPOINT in assets/js/analytics-config.js.

No external source applies; this is a state of the project, not a claim.

FLG-007 high severity

Search Console verification and sitemap submission were not possible

The sitemap, robots.txt and feed are generated and valid, but the property cannot be verified from this environment, so no submission was made and no query data exists.

What it affects: The content plan cannot be validated against real search demand until this is done.

How it is handled on the site: Documented on the discoverability and open-questions pages as a pending step rather than reported as complete.

How to close itVerify the property with a DNS or file method, submit /Affil3/sitemap.xml, and check coverage after a week.

Sources: developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap

FLG-011 high severity

A short link returned a product that was never submitted

Observation C for link.amazon/B0c8moW59 resolved to ASIN B0DHZTCNR5, a ThermoMaven digital meat thermometer. That product is not among the five submitted links, is not in any brief, and was never requested. The other observations of the same link returned a checkpoint page and the Chefman TurboFry. A link that can open an unrelated product is a buyer-facing risk, not merely a data-quality problem: a reader who clicks it may land on an item the article does not describe.

What it affects: If this link is ever published, a reader could be sent to the wrong product, which would breach the requirement not to make misleading claims about a product and would misrepresent what the page is recommending.

How it is handled on the site: The link is not published anywhere on the site. The observation is recorded in the product register with its date so the pattern is visible.

How to close itRetire the short link. Use canonical tagged product URLs, which point to one ASIN and cannot drift.

Sources: www.amazon.com/dp/B0DHZTCNR5

FLG-004 medium severity

No prices or ratings are published anywhere on the site

Amazon permits price and availability display only where Amazon serves the link containing the data or where the data is obtained through the Creators API or PA API. This site has no API credentials. Prices also change hourly, and Amazon states it cannot confirm a price until an order is placed.

What it affects: Readers must click through to see a price. This is a deliberate limitation, not an oversight.

How it is handled on the site: Every product card links to the live listing. No price, star average or review count is printed.

How to close itApply for Creators API access; if granted, add a price module that renders API-sourced data and never caches it beyond the permitted window.

Sources: affiliate-program.amazon.com/help/operating/policies · www.amazon.com/gp/help/customer/display.html

FLG-005 medium severity

No Amazon product imagery is used

Program Content may not be altered, and image caching is restricted under the IP License. Republishing listing photography without the licensed tools is a common breach. The site therefore uses typographic product cards and no third-party images.

What it affects: The design is text-forward. A photo-led design would need either licensed API images or original photography.

How it is handled on the site: Monogram tiles only. No external asset requests in the page.

How to close itIf visual richness is wanted, commission original photography or use the Creators API image endpoint once approved.

Sources: affiliate-program.amazon.com/help/operating/policies

FLG-008 medium severity

No product was physically tested, and two listings have no narrative review summary captured

Every product statement on this site is drawn from the listing as retrieved on 2026-11-20. No unit was purchased or tested. For the Chefman dual basket and the CHEF iQ Sense probe, Amazon's AI-generated review summary text was not captured during retrieval and is therefore left blank rather than characterised.

What it affects: The site can report specifications with confidence and user sentiment only where it was actually displayed.

How it is handled on the site: Stated in the editorial standards and in each guide's verification note.

How to close itEither capture the summaries on a second pass with the retrieval date recorded, or fund a test unit and publish measured results.

Sources: www.amazon.com/dp/B0CDY277D3 · www.amazon.com/dp/B0DZFD6R9Z

FLG-009 medium severity

The 'AI generates the articles' requirement conflicts with Amazon policy

The brief asks for an AI-powered engine that generates product articles. The Program Policies prohibit using Program Content or Special Links to develop or improve machine learning models without prior written approval. Generating articles from scraped listing text would sit inside that prohibition.

What it affects: Automation was therefore limited to checks, generation of the sitemap and feed, and link validation. Prose was written, not generated from listing text.

How it is handled on the site: Described on the automation page as a deliberate boundary rather than a missing feature.

How to close itScope any future model use to our own notes and non-Amazon sources, with a human editor signing each page.

Sources: affiliate-program.amazon.com/help/operating/policies

FLG-010 low severity

Internal navigation uses relative links from the CNAME-free Pages root

The site is served from a project path (/Affil3/) rather than a custom domain. Some relative-link forms resolve differently at the root than in a subdirectory, which can produce broken links on a project page if absolute paths are not used consistently.

What it affects: Handled by prefixing every internal link with the base path. Any future move to a custom domain requires changing one constant.

How it is handled on the site: The link checker runs on every build and fails on a broken internal link.

How to close itIf a custom domain is added, set the base path to empty and re-run the checks.

Sources: docs.github.com/en/pages
