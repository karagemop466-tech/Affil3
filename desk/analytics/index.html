Research desk · Measurement & analytics

Five events, zero surveillance

Click and conversion measurement ships before content scales. The client (assets/js/analytics.js) is privacy-preserving by construction: no cookies, no third-party beacons, no IP or user-agent storage. The brief asks for a self-hosted analytics endpoint and 'the five defined events'; the brief doesn't enumerate the events, so this register defines five and flags the gap (Q-05, FLG-008).

The event register

IDEventFires whenPayload
E1page_viewA page loadspath only (no query strings, no identifiers)
E2product_impressionA product card scrolls into view (once per card per session)product id only

Privacy rules

No cookies, no third-party beacons, no IP or user-agent storage, no cross-site identifiers. Events post only to a first-party endpoint when the site owner configures one (currently not deployed — FLG-006); otherwise they aggregate in the visitor's own localStorage.

Deployment status

Endpoint not deployed (FLG-006) GitHub Pages serves static files only. The collector is ready at server/collect.js (Node, standard library only): deploy it anywhere Node runs, then set <meta name="ck-endpoint"> on each page. Until then, event counts aggregate in your own browser — you can see them in DevTools under localStorage.ck_events_v1.

Conversion measurement

Outbound clicks (outbound_click) are our on-site purchase-intent signal. Reported orders come only from Associates Central reports and land in the campaign ledger with a report reference. We join the two only at the report level; we never model or forecast conversions.
