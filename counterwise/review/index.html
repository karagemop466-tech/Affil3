  • FLG-001blockerirregularity raised 20 November 2026 · needs review

    All five supplied link tokens are nine characters; the listings they resolved to carry ten-character identifiers

    B04G1MEwY, B02NbDxp3, B00hJ57DV, B0c8moW59 and B0f3GKalj are each nine characters long — countable from the strings themselves. The four pages they landed on sit at /dp/B0CDY277D3, /dp/B09B7SB46R, /dp/B08DKYBTPH and /dp/B0DZFD6R9Z, all ten characters, and none of those ten characters matches the nine in the link. So the token in the link path behaves like a redirect code, not like the catalog identifier of the product. No `intended_asin` is recorded for any row until the program owner confirms one.

    For a reader: None. Readers are sent to a listing page this project actually loaded, not to a guessed identifier.

    Action to close it: Owner confirms the intended listing per link; the gate then allows the ASIN into `intent` and unlocks Product structured data.

  • FLG-002blockerrevenue-risk raised 20 November 2026 · mitigated in build, needs in-account proof

    No observed destination carried a tracking tag

    The four resolved destination URLs carry lv, btn_type, gaOptInStatus, btn_ref, channelId, plpRedirect and (in two cases) th and sbo. None carries `tag=`. Amazon's Special Links rule quoted in the register requires the Associates tag as a URL parameter on every link placed on the site. A link with no tag earns nothing, however good the traffic is.

    For a reader: None for the reader; the reader lands on the right listing.

    Action to close it: This site does not publish the supplied links. Every outbound link it does publish is rebuilt as https://www.amazon.com/dp/<observed-id>?tag=shopnow047c-20 and the gate refuses to build if the tag is missing. Then test one link per product in-account before scaling.

    Evidenceaffiliate-program.amazon.com/help/operating/data/links.json → observed_query_params per row
