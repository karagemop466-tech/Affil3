Measurement

Click and conversion measurement, built and deliberately unarmed

Five events, one collector, one ledger and no numbers — because a static host is not running the collector yet and inventing a dashboard would be the worst possible first act. This page is the honest version of "analytics is set up".

State: endpoint (unset) · status not-deployed · ledger rows 0. While the endpoint is empty the page queues events in this browser's localStorage and sends nothing anywhere. Setting one value in data/config.json and rebuilding turns collection on; the queue then flushes once.

The five events

IDEventFires onDecision it serves
EV-01page_viewa guide, gear, cluster or summary page finishes loadingwhich entry pages bring strangers in, which decides where internal links and the next topic go
EV-02product_link_clicka click on any link carrying data-outbound, i.e. every tagged Amazon linkthe only signal that says a page made someone want to look at a listing; separates a read page from a useful one
EV-03comparison_startedtwo products selected in the comparison filter formwhich pairings readers actually want side by side, which is what decides the next comparison page
EV-04checklist_item_toggleda buyer checks a line in a decision checklistwhich criteria people actually use, which is how a guide earns its next revision without guessing
EV-05email_signup_submittedthe reader-capture form is submitted, whether or not capture is enableddemand for a list before we take on storing addresses; today it measures interest in something we cannot yet deliver, which is exactly the number we need

Payloads

EventProperties
page_viewpage: string, path only · kind: guide | gear | cluster | summary | other · referring_path: string, same-site only, empty for unknown
product_link_clickpage: string, path only · product_id: P-xx · link_state: pending-test | in-account-confirmed · placement: rail | gear-page | guide-cta | table | footer
comparison_startedpage: string · product_ids: array of two P-xx · cluster: string
checklist_item_toggledpage: string · checklist: string id · item: string id · checked: boolean
email_signup_submittedpage: string · capture_enabled: boolean · outcome: queued | disabled-noop

Privacy posture

  • no IP address is stored, read or logged
  • no cookie and no local identifier beyond the browser's own session queue
  • no third-party endpoint receives a request
  • navigator.doNotTrack or the global privacy control signal stops collection before the first event
  • the page path is stored, never the query string, so a tagged outbound URL cannot leak a session token into the log
  • retention is the append-only file; there is no user-level profile to delete

Turning it on

python3 tools/collector.py serve --port 8099      # or any host that can run one process
# data/config.json → measurement.endpoint = "https://metrics.example.org"
python3 tools/build.py && python3 tools/gate.py

The Amazon side of the ledger — orders, commission, product category — may only be written from an authorized first-party report, with the report named on the row. That part has a human gate on purpose: python3 tools/ledger.py append --help.

What will not appear here

No conversion score, no revenue forecast, no modelled earnings, and no percentage attributed to a page that has been visited by nobody but a build script.
