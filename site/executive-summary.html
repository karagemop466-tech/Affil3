The one-paragraph version

An affiliate site was asked for: five product links, a tracking ID, automation, measurement, compliance. What exists is a working publishing system that refuses to lie — pages generated from a register, a build gate that will not deploy without disclosure and without a properly tagged link, an event schema, an empty-but-correct campaign ledger, and a live GitHub Pages site. What does not exist is any verifiable fact about the five products, because their identifiers could not be resolved from this environment, and a site that invented them would be worth less than nothing.

The finding that changes the brief

Amazon's programme policies do not permit the version of "AI-powered affiliate platform" that reads the market for you. The IP licence bars robots and data mining against Program Content, bars storing Program Content images at all (a link to them may be stored for 24 hours), caps other product data caching at 24 hours, bars displaying prices or ratings except from a link Amazon serves or an API call under licence, bars using Program Content to develop or improve machine-learning models, and bars accessing the APIs "for the purpose of aggregating, analyzing, extracting, or repurposing" their content without express prior written approval. A 2026 addition requires any autonomous Agent touching that content to name itself in the HTTP User-Agent string as Agent/[name] and not to mimic human interaction.

An affiliate automation platform built on scraping or warehousing Amazon data is not a risky version of the plan. It is a different plan, and the risk is the whole account: the agreement lets Amazon stop paying commissions earned anywhere on the site.

Everything this repo automates therefore sits on our side of the line: intake, validation, generation, gating, scheduling, reporting. The Amazon-facing steps are one human, five minutes per link, and a documented protocol.

Constraints that shaped the build (each one is a rule, not a preference)

  • Disclosure is not optional or footnoted. Operating Agreement §5 requires the exact associate sentence, clearly and prominently; the FTC's standard pushes it close to the recommendation and hard to miss, so it is in the layout, above the fold, on every page. [S01] [S20]
  • Links must be the tagged format, direct, and correctly formatted. Improperly formatted or indirect links are disqualified purchases — the traffic still happens, the commission does not. [S03] [S04]
  • No prices, no ratings, no review quotes, no Amazon images. All four are licence-restricted without API access, which is unconfirmed. The tables look sparse for exactly this reason. [S06] [S07] [S08]
  • No self-purchase, no synthetic clicks. Testing the link by buying through it is prohibited, which is why the protocol verifies the address bar and waits for a real reader. [S12]
  • No price alerts or deal pages. Price tracking and alerting functionality is prohibited; time-limited promotional copy has to be pulled the day it expires, which a static site should not pretend to do. [S13] [S15]
  • There is a clock. Three qualifying sales within 180 days of application, or the application can be withdrawn and the account is not reinstatable. Nobody here knows when it started. That is question Q-01 and it outranks every design decision. [S17]

What ships today

  • A GitHub Pages site: front page, shelf, 5 product-intent records, 5 guides, 2 topic clusters, a reader-facing status page, and 7 operator surfaces (source register, suggestions, questions, flags, ledger, measurement, gate).
  • A deterministic builder and a 13-check publish gate in CI that fails the deploy on a missing disclosure, a mistagged link, an unlicensed field, an unsupported claim string, or a sitemap/feed/calendar disagreement.
  • An intake tool that records confirmations with dates and keeps intended and observed values in separate fields.
  • A cookieless event collector with a published schema, five defined events, and a refusal to accept a row that is not one of them.
  • A campaign ledger that will not take a number without naming the first-party report it came from.

What we need from you — the short version of the questions page

  1. The application date and qualifying-sale count (Q-01). Without it the roadmap has no deadline and may be pointless.
  2. Confirmation that shopnow047c-20 exists on the account and that this site's URL is registered (Q-02).
  3. The five link test, five minutes each (Q-03) — this is the only thing standing between the shelf and revenue.
  4. Whether API access exists, or will be applied for (Q-04). It decides whether comparison tables with real fields are ever buildable.
  5. The niche and the byline (Q-09, Q-10), and a definition of success worth measuring (Q-18).
  6. Approve or reject the 28 suggestions; 8 are proposed and waiting, and none of them will self-implement.

Honest statement of the risk

This site is a correct foundation with almost no demand evidence under it. It is hosted on a project path at GitHub Pages, has no backlinks, no measured queries, and no traffic history, so "optimise campaigns to maximise affiliate revenue" is currently an instruction with nothing to optimise against. The plan in the register is deliberately sequenced: resolve the links, get indexed, write twelve guides, read the queries, and only then automate the parts that measurement justifies. Anyone who promises revenue from a five-ASIN starter shelf before that point is guessing.
