Automation and gates

What the machine does, and what it refuses to do

The rule for this site: automate anything that can be checked deterministically, and put a hard gate in front of anything that requires a judgement. A build that fails is cheaper than a page that is wrong.

Updated 2026-11-20Runs on every push
Read this first

The original brief asked for an engine that researches products, writes articles and optimises campaigns automatically. Two of those are constrained by Amazon's own policies and one cannot be done without data the site does not have yet. The table below says which is which rather than pretending all three shipped.

The boundary

What the gate actually checks

tools/validate.mjs runs on every push and blocks publication on any of the following. These are hard failures, not warnings.

  1. Disclosure present on every page. Both the FTC wording and the exact Amazon Associates statement must appear in the HTML.
  2. Every outbound Amazon link is tagged and labelled. The tag=shopnow047c-20 parameter must be present, the link must carry rel="sponsored", and the literal words Paid link must sit beside it.
  3. Identity agreement. For every published product, intended_asin must equal the ASIN embedded in intended_listing_url, and the resolution status must be resolved.
  4. No price or rating leakage. A currency pattern or a star-rating pattern in the generated HTML fails the build, because both are things this site has decided never to publish.
  5. No unresolved product in the catalogue. A product without a verified ASIN cannot be marked published.
  6. Internal links resolve. Every relative href must correspond to a generated file.
  7. Structured data parses. Every JSON-LD block is parsed and required fields are asserted.
  8. Sitemap and feed agree with the pages. Every indexable route appears in the sitemap exactly once.

The gate is deliberately blunt. It cannot tell whether a sentence is true — that remains a human job — but it can make the mechanical failures impossible to ship.

Product data path, if API access is ever granted

Any future automation must target the Creators API. PA-API 5 is deprecated and returns an access-denied error to integrations that still call it. C-13

  1. Obtain credentials: a key pair plus the Associates tag, both assigned to this account. C-14
  2. Fetch only the fields the design uses. Do not cache image content; the licence limits even a stored image link to 24 hours. C-12
  3. Render price only inside an Amazon-served element, and never in a cross-retailer comparison without both the lowest new and lowest used price. C-09 C-10
  4. Re-verify at build time that no cached figure is older than the permitted window.

What is not automated, on purpose

  • Choosing which product to recommend. That carries a legal disclosure obligation, so a named editor owns it.
  • Writing the prose. A model may not be fed listing content, so there is no compliant way to generate these articles from the data the site holds.
  • Deciding whether a claim is true. The validator checks that a source exists for a claim; it cannot check that the source says what we think it says.
  • Publishing a new guide. A new file appears in the sitemap and feed automatically, but the gate runs first and a human signs the page.
Failure direction

When the gate is unsure, it fails the build. A blocked deploy costs an hour; a published page with a missing disclosure or an untagged link costs the account.
